# Image Lists Reference

**doc_type:** reference

Complete reference for container image lists used in openCenter AirGap.

## Overview

openCenter AirGap maintains separate image lists for different purposes:

1. **opencenter-images.txt** - Platform services (20+ services)
2. **kubespray-images.txt** - Kubernetes infrastructure
3. **all-images.txt** - Combined list

## Image List Files

### 1. opencenter-images.txt

**Location:** `config/opencenter-images.txt`

**Purpose:** openCenter platform service images

**Contents:**
- FluxCD controllers
- Gitea
- Cert-Manager
- Ingress & Gateway API
- Keycloak
- Observability stack (Prometheus, Grafana, Loki, Tempo, Mimir)
- Storage (Longhorn, CSI drivers)
- Policy & Security (Kyverno, RBAC Manager, Sealed Secrets)
- Backup (Velero)
- Harbor registry
- Headlamp UI
- Weave GitOps
- MetalLB
- Postgres Operator
- Kafka

**Count:** ~137 images

**Generated by:** `scripts/build/generate_opencenter_images.py`

**Source:** Extracted from `assets/gitops-base/` manifests

### 2. kubespray-images.txt

**Location:** `config/kubespray-images.txt`

**Purpose:** Kubernetes cluster infrastructure images

**Contents:**
- Kubernetes control plane (kube-apiserver, kube-controller-manager, kube-scheduler, kube-proxy)
- etcd
- CoreDNS
- CNI plugins (Calico, Cilium, etc.)
- Metrics server
- Ingress controllers
- DNS cache
- Pause container

**Count:** Varies by Kubernetes version (~50-100 images)

**Generated by:** `scripts/build/generate_image_lists.sh`

**Source:** Scanned from kubespray repository manifests

**Note:** Requires kubespray repository at `assets/kubespray/kubespray-master`

### 3. all-images.txt

**Location:** `config/all-images.txt`

**Purpose:** Combined list of all images

**Contents:** Kubespray images + openCenter images (deduplicated)

**Count:** ~200-250 images total

**Generated by:** `scripts/build/generate_image_lists.sh`

## Generation

### Generate All Lists

```bash
./scripts/build/generate_image_lists.sh
```

Output:
```
Generated files:
  1. config/kubespray-images.txt
  2. config/opencenter-images.txt
  3. config/all-images.txt
  4. build/repository-scans/ (detailed scan results)
```

### Generate Only openCenter Images

```bash
python3 scripts/build/generate_opencenter_images.py \
    --output config/opencenter-images.txt
```

### Update After Changes

```bash
# After updating gitops-base or genestack
git -C assets/genestack pull
./scripts/build/generate_image_lists.sh

# After updating kubespray repository
git -C assets/kubespray/kubespray-master pull
./scripts/build/generate_image_lists.sh
```

## Usage

### View Image Counts

```bash
# openCenter images
grep -v "^#" config/opencenter-images.txt | grep -v "^$" | wc -l

# Kubespray images
grep -v "^#" config/kubespray-images.txt | grep -v "^$" | wc -l

# Total images
grep -v "^#" config/all-images.txt | grep -v "^$" | wc -l
```

### Extract by Category

```bash
# Get only observability images
grep -A 50 "# Observability" config/opencenter-images.txt | \
    grep -v "^#" | grep -v "^$"

# Get only storage images
grep -A 50 "# Storage" config/opencenter-images.txt | \
    grep -v "^#" | grep -v "^$"
```

### Check for Specific Image

```bash
# Check if image is in list
grep "prometheus" config/all-images.txt

# Check which list contains image
grep -l "prometheus" config/*-images.txt
```

### Export for External Tools

```bash
# Plain list (no comments)
grep -v "^#" config/all-images.txt | grep -v "^$" > images-plain.txt

# JSON array
grep -v "^#" config/all-images.txt | grep -v "^$" | \
    jq -R . | jq -s . > images.json

# CSV format
echo "image" > images.csv
grep -v "^#" config/all-images.txt | grep -v "^$" >> images.csv
```

## Integration with Build Process

### kubespray-offline Integration

The `opencenter-images.txt` is automatically copied to:
```
build/kubespray-offline/imagelists/additional_images.txt
```

kubespray-offline will:
1. Read `images.txt` (core Kubernetes images)
2. Read `additional_images.txt` (openCenter platform images)
3. Download all images during `download-all.sh`
4. Save to `outputs/images/*.tar.gz`

### Zarf Packaging

Zarf packages images from:
1. Local podman/docker (loaded from kubespray-offline outputs)
2. Image references in `zarf.yaml` components

## Maintenance

### Adding New Images

**For openCenter platform services:**

1. Add image to genestack manifests
2. Regenerate list: `./scripts/build/generate_image_lists.sh`
3. Verify: `grep "new-image" config/opencenter-images.txt`

**For Kubernetes infrastructure:**

1. Update kubespray version in `config/versions.env`
2. Update kubespray repository: `git -C assets/kubespray/kubespray-master pull`
3. Regenerate list: `./scripts/build/generate_image_lists.sh`

### Removing Images

**For openCenter platform services:**

1. Remove from genestack manifests
2. Regenerate list: `./scripts/build/generate_image_lists.sh`

**For Kubernetes infrastructure:**

Managed by kubespray repository based on Kubernetes version.

### Version Updates

```bash
# Update Kubernetes version
vim config/versions.env  # Change KUBERNETES_VERSION

# Update repositories
git -C assets/kubespray/kubespray-master pull
git -C assets/genestack pull

# Regenerate lists
./scripts/build/generate_image_lists.sh

# Review changes
git diff config/*-images.txt
```

## Troubleshooting

### Empty kubespray-images.txt

**Symptom:** kubespray-images.txt is empty or has few images

**Cause:** Kubespray repository not cloned or scan failed

**Solution:**
```bash
# Clone kubespray repository
git clone https://github.com/kubernetes-sigs/kubespray.git \
    assets/kubespray/kubespray-master

# Regenerate lists
./scripts/build/generate_image_lists.sh
```

### Missing openCenter Images

**Symptom:** Expected images not in opencenter-images.txt

**Cause:** Images not in genestack or pattern not matched

**Solution:**
1. Check genestack: `find assets/genestack -name "*.yaml" | xargs grep "image:"`
2. Review scan results: `cat build/repository-scans/genestack-scan-details.json`
3. Add manually to `config/opencenter-images.txt` if needed

### Duplicate Images

**Symptom:** Same image in both lists

**Cause:** Image used by both Kubernetes and platform services

**Solution:** This is expected. Keep in both lists for clarity.
